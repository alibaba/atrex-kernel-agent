# Implementation Plan: Hidden-Teacher Distillation Campaign

## Overview

Add an opt-in offline `teacher-distill` campaign that measures an immutable expert implementation, asks the Agent to create a naive target-framework V1 from the PyTorch/reference V0, and optimizes the Candidate until it reaches the Teacher target. The Teacher stays outside the Candidate workspace during optimization. The mode uses a physically sanitized knowledge view, production-policy enforcement, per-iteration Teacher progress, final same-allocation ABBA verification, bounded long-horizon escalation, and evidence-backed draft generation. Existing standard campaigns must retain their current CLI and runtime behavior.

## Definition of Done

A first release is complete when all of the following hold:

1. A valid command with `--campaign-mode teacher-distill` and a valid Teacher solution bundle can create and resume a single-operator, single-framework campaign.
2. The Teacher passes framework/policy, full-workload correctness, multi-seed, and benchmark validation before an optimization Agent runs.
3. Candidate V0 remains the PyTorch/reference baseline; Candidate V1 is generated by the Agent in the selected framework without Teacher/operator-specific implementation knowledge.
4. Optimization sessions can see only a content-addressed sanitized gpu-wiki, cannot see `reference-projects`, and run under an audited forbidden-access policy.
5. Every measured Candidate iteration records `teacher_progress` without changing ordinary memory behavior.
6. Success requires full correctness, multi-seed correctness, geomean ratio `<= 1.05`, worst-shape ratio `<= 1.10`, and an authoritative same-allocation ABBA PASS.
7. The campaign ends with exactly one of `SUCCESS`, `PLATEAU`, `BUDGET_EXHAUSTED`, `INFRA_ERROR`, or `TEACHER_LEAKAGE_VIOLATION`.
8. Consecutive stalls can invoke one isolated long-horizon episode without allowing the incumbent HEAD to regress.
9. Completion creates deterministic evidence plus reviewable drafts; it never edits the canonical gpu-wiki automatically.
10. Existing leaderboard/production, framework dispatch, workload bucketing, layer, long-horizon, and memory tests remain green.

## Architecture Decisions

### Public mode boundary

- Add `--campaign-mode {standard,teacher-distill}`; default remains `standard`.
- `teacher-distill` requires an explicit `--framework` and `--teacher-solution`.
- It requires production mode and rejects leaderboard mode, framework auto-dispatch, `--layer`, and workload bucketing.
- It stops at Teacher parity. Frontier 10→100 work starts in a separate warm-start campaign.

### Version model

```text
V0 = immutable PyTorch/reference baseline
V1 = Agent-authored naive framework baseline; correctness gate only
V2+ = profile-driven Candidate improvements
Teacher = private target artifact, never a Candidate commit
```

### Module boundary

Create a top-level `teacher_distill/` package. `TeacherDistillCampaign` owns Teacher lifecycle, knowledge isolation, target verification, terminal status, and distillation. The existing `orchestrator.optimize.Campaign` remains the Candidate optimization engine.

The Candidate engine gains only narrow, optional seams:

- a `StopPolicy` protocol;
- a runtime/knowledge-link override;
- a prompt search-policy directive;
- per-session environment policy values.

Defaults reproduce current behavior.

### Public and private state

Candidate-visible, Git-tracked state:

```text
kernel_opt_<name>_<framework>_<platform>/
├── campaign_lock.json
├── teacher_target.json       # opaque ID + metrics only
├── kernel.py
├── memory/
├── plans/
└── profiles/
```

Supervisor-private state outside the Candidate workspace:

```text
<work-root>/.atrex_teacher_campaigns/<campaign-id>/
├── private_config.json
├── provenance.json
├── teacher_bundle_hash.json
├── benchmark_runs/
├── abba/
├── audit/
└── distillation/
```

The public state must not contain Teacher paths, source code, project revision, or source-project identity.

### Teacher bundle contract

`--teacher-solution` points to a directory containing:

```text
teacher_solution/
├── kernel.py
├── solution.json
├── provenance.json
└── helpers/                  # optional, self-contained
```

`provenance.json` schema requires canonical operator ID, aliases, source project, revision, license, framework, architecture, and knowledge deny selectors. Inputs are immutable after campaign creation and content-hashed recursively.

### Knowledge isolation

Build a physical, read-only, content-addressed knowledge view. Include target hardware facts, target DSL/API material, generic profiler guidance, generic optimization cards, and cross-operator knowledge. Exclude current-operator implementation journeys, pitfalls, references, Teacher source/project, full `reference-projects`, and public-web fallback. Generate a pruned manifest and self-contained README; reject links that escape the sanitized root.

This is `hidden-audited`, not a security sandbox. Common forbidden file/network commands are mechanically detected and terminate the session. Results must state this integrity level.

### Stop semantics

The default policy preserves the current peak-utilization stop. `TeacherStopPolicy` computes:

```text
candidate_geomean / teacher_geomean <= 1.05
max(candidate_shape / teacher_shape) <= 1.10
```

A provisional pass triggers authoritative same-allocation ABBA. Only ABBA PASS produces `SUCCESS`. ABBA FAIL resumes optimization; ABBA infrastructure errors do not count as optimization stalls.

### Stall escalation

- Ordinary rounds remain single-category and monotonic.
- At three consecutive no-promotion rounds, run one isolated long-horizon episode.
- Temporary regressions are allowed only in its private worktree.
- Only an ABBA-verified improvement is squash-promoted.
- If the episode fails, perform one partial-memory restart and continue.
- Exhausted configured stall/budget limits produce `PLATEAU` or `BUDGET_EXHAUSTED`; targets never drift.

### Distillation

1. A deterministic Evidence Builder creates IDs and immutable evidence manifests.
2. A clean Distillation Agent writes drafts using only citable evidence.
3. A validator rejects unsupported numbers, masked/reverted evidence used as proof, Teacher hypotheses marked verified, copied Teacher code, and unsourced hardware facts.
4. A post-run Teacher gap analysis may read Teacher code, but every conclusion starts as `hypothesis` and is not promotion-eligible.
5. Canonical gpu-wiki promotion remains manual and CI-gated.

## Interface Contracts

### CLI additions

```text
--campaign-mode standard|teacher-distill       default: standard
--teacher-solution DIR                         required in teacher-distill
--teacher-geomean-ratio FLOAT                  default: 1.05
--teacher-shape-ratio FLOAT                    default: 1.10
--teacher-stall-before-episode INT             default: 3
--teacher-partial-restarts INT                 default: 1
--teacher-private-root DIR                     default: <work-root>/.atrex_teacher_campaigns
```

Teacher mode validation:

- `--framework` required;
- `--optimization-mode production` required;
- `--no-workload-bucketing` required in the first release;
- `--layer` forbidden;
- cross-framework Teacher forbidden;
- ratio values must be finite and `>= 1.0`;
- Teacher bundle/provenance must validate before creating Candidate state.

### Stop policy

Suggested internal interface:

```python
@dataclass(frozen=True)
class StopDecision:
    status: Literal["SUCCESS", "CONTINUE", "INFRA_ERROR"]
    reason: str

class StopPolicy(Protocol):
    def evaluate_accepted_iteration(
        self,
        campaign: "Campaign",
        version: int,
        memory: dict,
    ) -> StopDecision:
        ...
```

Budget and stall exits remain owned by the optimization engine and are mapped to Teacher terminal states by the supervisor.

### Optional memory extension

```json
{
  "teacher_progress": {
    "target_id": "opaque-id",
    "candidate_to_teacher_geomean_ratio": 1.18,
    "worst_shape_ratio": 1.27,
    "worst_shape_key": "shape_4",
    "geomean_gate_met": false,
    "shape_gate_met": false,
    "provisional_target_met": false,
    "abba_status": "NOT_RUN",
    "final_candidate_to_teacher_ratio": null
  }
}
```

Allowed ABBA statuses: `NOT_RUN`, `PASS`, `FAIL`, `INFRA_ERROR`.

### Terminal result

Write a machine-readable private `result.json` and print one terminal line. Result statuses:

- `SUCCESS`
- `PLATEAU`
- `BUDGET_EXHAUSTED`
- `INFRA_ERROR`
- `TEACHER_LEAKAGE_VIOLATION`

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Hidden mode leaks through absolute paths or shell tricks | High | Physical sanitized view, no reference-project link, generic process/shell audit, violation status, explicit non-security threat model |
| Existing `Campaign.run()` regresses | High | Optional StopPolicy with default characterization tests; lazy Teacher import; full existing suite at every checkpoint |
| Teacher and Candidate measurements are not comparable | High | Same immutable evaluator/workload/config hashes; full shape coverage; final same-allocation ABBA |
| Teacher target is unattainable in selected DSL | Medium | Same-framework production gate; hard budget; honest PLATEAU/BUDGET_EXHAUSTED outputs |
| Knowledge filtering removes framework docs needed for V1 | Medium | Inclusion report and fixture test proving generic DSL/API docs remain available |
| Knowledge filtering misses aliases | High | Required provenance aliases + op identity + manifest aliases + deny-selector union; fail closed |
