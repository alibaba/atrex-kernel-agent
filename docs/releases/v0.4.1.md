# Atrex Kernel Agent v0.4.1

Light now runs persistent optimization campaigns. Each coding agent keeps its Session
and Git history across Episodes. The Supervisor records measurements and reviews exact
commits, and accepted submissions determine the campaign's best kernels.

## Highlights

### Persistent Sessions and reviewed submissions

- **Agent-owned Git.** Each lineage starts with a Git repository initialized from the
  starting source. The Agent decides when to evaluate it. An Episode ends when the Agent
  finishes a segment, and the next segment resumes the same conversation, workspace,
  branches, and uncommitted edits.
- **Exact-commit review.** `submit-kernel` uses a saved full Evaluate with passing
  correctness and complete per-Shape performance for that commit. Fast permits declared,
  reproducible compute libraries. Performance requires self-authored core computation.
  Ultra also requires an explicit DSL. Submissions have no minimum speedup requirement.
  ABBA is available as a separate, explicit measurement.
- **Shared campaign evidence.** One Measurement Store holds source snapshots, results,
  and execution attempts. Pooled lineages can share peer Git refs and versioned
  Direction/Experiment records. Accepted submissions determine lineage and global
  winners while each Agent retains control of its own HEAD.
- **Session and measurement budgets.** The workflow imposes no active-time deadline
  on Episodes or Reviews. Completed segments and main-Agent tokens can limit campaign
  admission. GPU queue, request, and per-step deadlines remain independently configurable.

See the [Light architecture](../design.md) for the campaign lifecycle and submission
rules.

### Tools, execution, and recovery

- **DSH and operator tooling.** `--agent-cli dsh` selects
  [DeepSeek Harness headless Sessions](../dsh-harness-adapter.md).
  The [Light skill](../../skills/atrex-aka-light/SKILL.md) covers setup and launch. The
  [inspection tools](../../observability/README.md) and read-only
  [Dashboard](../optimization-dashboard.md) show lineage progress, separate Agent and
  Review usage, submitted kernels, and Runtime and Agate calls. Operators can export
  exact-commit sources and the associated measurement evidence.
- **OpenSSH GPU execution.** A provisioned host can run native Atrex-Bench Evaluate
  and same-allocation ABBA on one selected GPU, with diagnostics for supported NVIDIA,
  AMD, and T-Head PPU environments. See the [OpenSSH backend](../ssh-backend.md) for
  supported operations and isolation modes.
- **Editable source trees and native Agate contracts.** The default `source_tree` layout
  exposes `kernel.py` as the editable evaluator entry point, with optional helpers under
  `impl/`. Light discovers supported Agate options from the installed SDK while keeping
  evaluator inputs and execution authority under Supervisor control.
- **Recovery and publication.** Matching in-flight Evaluate requests share one
  execution. Interrupted collections retain accepted job IDs, and completed batch
  evidence can be reused for matching requests. Resource publication
  can recover interrupted writes, and workspace initialization preserves existing
  Agent Git state. See [measurement recovery](../measurement-records.md#failure-and-recovery-policy)
  and [workspace publication](../workspace-publication.md).

## Upgrading from v0.4.0

1. **Install matching wheels and checkout resources.** Build and reinstall from the
   release checkout. Framework, Light, and Dashboard use Python distribution version
   `0.3.0`. The repository release is `v0.4.1`. Remove retired distributions such as
   `atrex-aka-legacy` and `atrex-aka-observation-long-horizon` from a reused environment
   before installing the new wheels. See [installed startup](../application-plugin-migration.md#distribution).
2. **Use a new campaign directory.** Continue older handoff/promotion campaigns with
   their original checkout and installed packages. See [migration and rollback](../design.md#migration-and-rollback).
3. **Update launch scripts.** Rename `--op-dir` to `--problem` and `--workspace`
   to `--workspace-base`. Remove the optimizer's `--` separator. Choose `fast`
   (default), `performance`, or `ultra` in place of `leaderboard` and
   `production`. Ultra requires `--framework`. The [Quick Start](../quickstart.md#launch-light)
   has complete examples.
4. **Update report and measurement consumers.** Read accepted `submit-kernel` records
   and the Campaign Measurement Store in place of `episode-report` and promotion
   receipts. Native Evaluate defaults to five correctness cases per Shape, ten
   warmups, and twenty benchmark iterations. Remove the retired
   `workflow.config.numerical_validation` and `workflow.config.episode_timeout_seconds`
   options from launch patches.
